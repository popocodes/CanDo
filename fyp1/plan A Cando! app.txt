CanDo! — Final Master Blueprint (updated to match the running version)
Repository: https://github.com/popocodes/CanDo
(The original Unity + Firebase plan is kept in "plan A Cando! app (original Unity-Firebase).txt")


1. The Core Identity & ADHD Psychology

 App Goal: A gamified, visual-prompting web app that uses audio chunking and one-step-at-a-time chore flows to help children with ADHD (ages 5–12) complete chores without task paralysis.
 Mascot (Digital Body Double): Popo, a cosmic cat alien who guides the child, prevents loneliness, and gives immediate emotional feedback.
 Tech Stack (as built): Node.js + Express (server), SQLite via `sqlite3` (database, file cando.db), plain HTML/CSS/JavaScript front end (runs in any phone/tablet/desktop browser, no app-store install), Server-Sent Events (live updates), ntfy (parent push notifications).
 ADHD Design Rules:
 - No Ticking Numbers: a moving spaceship progress bar replaces countdowns.
 - Chunking: only one step is shown at a time.
 - Audio First: each step is read aloud (browser speech synthesis) so the child can put the phone down and clean with both hands; sound effects are synthesised with the Web Audio API (no audio files).
 - Asymmetric Gamification: no broken streaks or penalties; successes are celebrated (confetti, fanfare, stars). "No" at the check-in simply means "one more small round".


2. Global Systems

 Built-in Chore Database: 10 rooms x 5 micro-steps (server/choreTemplates.js), taken from "ADHD-Friendly 5-Step Chores by Room.txt", seeded into SQLite when a chore is assigned. Each step has text, a Popo hint and a Popo pose image. Safety notes (kitchen, laundry, entryway) are shown on the step screen.
 The "SoftLock" Distraction Monitor (browser -> server): the Page Visibility / window-blur events detect when the child leaves the app mid-chore. The server stores an alert (throttled to one per 45 s), pushes it live to the parent dashboard and sends an ntfy notification. When the child returns, Popo welcomes them back.
 Parent Notification Engine (ntfy): server/ntfy.js publishes through the ntfy JSON API (ntfy.sh or self-hosted; optional token or user:password; optional tap-to-open link). Events the parent can switch on/off:
 - Completion: "📸 Mission Accomplished! Leo finished 'Reset Your Room'. Check their proof photo!"
 - Distraction: "🚨 Task Paused: Leo left CanDo! at 4:15 PM."
 - Reward: "🎁 Reward Claimed! Leo spent 20 stars on '30 Mins iPad / Screen Time'."
 - Help: "🆘 Leo needs help with 'Reset Your Room'."
 Sending is fire-and-forget, so the app keeps working if ntfy is unreachable.
 Live updates: Server-Sent Events refresh the parent inbox, alerts and stats, and tell the child when a mission is approved.


3. Screen-by-Screen Breakdown

 Setup page (replaces "Screen 0: First-Time Setup") — /setup.html
 Four-step wizard shown automatically on first run: (1) family name + 4-digit parent PIN, (2) add explorers (name, colour, Popo avatar), (3) ntfy notifications with install instructions, topic generator and a "send test" button, (4) review and launch. Re-openable later with the parent PIN. The PIN is stored in the SQLite settings table.

 Screen 1: The Gateway ("Who is exploring today?")
 Grid of the children's avatars; tap a face to enter. A "Parent" lock button opens a PIN numpad (on-screen or keyboard). Kids are read from SQLite. If no kids exist a "Start setup" prompt is shown.

 Screen 2: The Space Base (Kid's Quest Hub)
 - Space Base room: Popo plus unlocked decorations; children spend stars to unlock items (lava lamp, star projector, alien plant, mars rover, disco orb).
 - Today's Quests (task board): assigned chores with stars reward, status (Start / Continue / Under Review) and safety notes.
 - Low Battery Mode: toggle that cuts a chore down to its 1–2 "good enough" key steps.
 - Mission Roulette: spinning wheel (canvas) that picks a chore to beat decision paralysis.
 - Star Store: real-world rewards; claiming deducts stars and notifies the parent.
 - Cosmic Arcade: boarded up until no chores are left to do (chores under parent review count as done); opens Cosmic Bubble Pop, a no-lose bubble game.

 Screen 3: Active Chore Mode (Micro-Step Flow)
 One Micro-Step card: instruction, Popo pose + hint, huge "Done! Next Step" button, Back, "Show Me! (AR)", "Listen", "I need help", and a collected-stars counter. The step is read aloud automatically. Progress is saved to SQLite per step.
 After the last step: check-in "Is the room clean enough for now?" with Yes / No (one more small round) / Send a photo / I need help.

 Screen 4: The 2D "Magic Lens" (On-Demand Visual Prompting)
 "Show Me!" opens the device camera (getUserMedia) with a target frame, scanner line and Popo showing the current step. Close with X. (Browsers only allow the camera on https:// or localhost.)

 Screen 5: Proof Photo Shutter & Celebration
 Camera snapshot (or "Choose a photo" fallback). The photo is uploaded to the server (public/uploads), the chore becomes "Pending approval", confetti + fanfare play, and the parent is notified. The child can go to the Cosmic Arcade while waiting. When the parent approves, the child sees: "Your parent approved your chore! You earned all your stars!"

 Screen 6: Parent Command Center (PIN protected)
 Tabs:
 - Approvals: stats row (waiting approvals, missions and stars this week, left-app events today, rewards to grant) and proof-photo inbox with Approve (+stars) and Gentle Redo (with a kind note for Popo to say).
 - Task Assigner: assign any of the 10 room templates to a child, create custom missions (own steps, stars), list/remove active missions.
 - Reward Maker: create/remove real-world rewards, mark claimed rewards as granted.
 - Activity & Distraction Log: live feed of completions, distractions, rewards, help requests, approvals.
 - Notifications: ntfy settings (server, topic, token, tap-to-open link, events, send test).
 - Cadets & PIN: add/remove children, change the 4-digit PIN.


4. Data Model (SQLite, file cando.db)

 settings (parent PIN, family name, ntfy config, setup_complete), kids, chores, chore_steps, rewards, reward_redemptions, room_decorations, alerts.


5. Differences from the original Unity + Firebase plan

 - Unity 2D app  -> responsive web app (HTML/CSS/JS), installed by simply opening the address in a browser.
 - Firebase Auth / Firestore / Storage / FCM -> Node.js + Express, SQLite, local photo uploads, ntfy push notifications.
 - ScriptableObject chore data -> server/choreTemplates.js.
 - Unity sprite/GIF animations -> Popo pose images (cropped from the character sheets) with CSS animations.
 - PlayerPrefs PIN -> PIN stored in the SQLite settings table (4 digits, checked by the server).
 - Kept the lightweight scope: single process, one database file, no accounts or cloud services required.


6. Running it

 npm install
 npm start        -> http://localhost:3000   (first run opens the setup wizard)
 Reset everything: stop the server and delete cando.db.
 Notification setup details: see README.md (section "Parent notifications with ntfy").
